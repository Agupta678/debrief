The pipeline

      
Three passes, in order

      
    
        
  1. 
          01
          
    Read for intent
    
          
    Every line gets scanned for the language people actually use to commit to something — "will," "needs to," "by Friday" — separating decisions from discussion.
    
        
    2. 
        
  2. 
          02
          
    Attach an owner
    
          
    Names near a commitment get linked to it. An action item with no owner gets flagged instead of silently dropped.
    
        
    3. 
        
  3. 
          03
          
    Rank by urgency
    
          
    Signals like "ASAP," "blocking," or a named deadline push an item up; open-ended items get marked for follow-up instead of buried.

Built in the open

        
Extraction runs on Claude, with a deterministic local engine as fallback if the API call fails. Accuracy is scored against a fixture set checked into the repo — npm run benchmark — not claimed in a headline.

      

      

        
One template, on purpose

        
Debrief ships a single default — the Stakeholder Update — refined until it's reliably good, instead of a template gallery to pick through. A template picker is the planned v2, once this one earns its keep.

      

      

        
Why "Debrief"

        
A debrief is the moment after the work where you extract what happened and what's next. That's the whole product, named for exactly what it does.
